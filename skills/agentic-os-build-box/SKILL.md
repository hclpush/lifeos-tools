# Build Box — Park an Unfinished Task

Captures an unfinished task as a checklist line in `000_Agent/dashboard/build-box.md`,
linked to a handover doc written for a cold-start session — so a future session (or a
future you) can pick the work back up with zero context.

## Vault Root

Set this to your Obsidian vault path. Replace the value below before installing:

```
VAULT = /path/to/your/obsidian/vault
```

All paths below are relative to it.

## How it fits together

- `000_Agent/dashboard/build-box.md` is the **data file**: one `- [ ]` line per parked task.
- `100_Todo/drafts/handover-<slug>-<date>.md` is the **handover doc**: everything a
  cold-start agent session needs to resume the work.
- **Optional renderer:** if you maintain a dashboard note that is regenerated by a script
  (e.g. `000_Agent/scripts/dashboard-render.py` rendering unchecked lines as linked chips),
  this skill re-runs it so the chip appears immediately. If you don't have a renderer,
  skip that step — the build-box file itself is the source of truth and works standalone.

Never write parked tasks into a rendered dashboard note directly — if a renderer exists,
it regenerates the note from scratch and wipes manual edits. Always append to the data file.

## Steps

1. **Get the task name.**
   - If invoked with an argument (`/agentic-os-build-box fix the selector`), use it.
   - Otherwise infer it from the current conversation — the piece of work that is clearly
     unfinished. If genuinely ambiguous (several candidates), ask in one line.
   - Chip-size the label: ≤ 60 chars, lowercase-ish, no trailing punctuation ("fix
     LinkedIn news-rail selector" beats a full sentence).

2. **Find or create the handover doc.**
   - Check `100_Todo/drafts/` for an existing handover for this task
     (convention: `handover-<slug>-YYYY-MM-DD.md`). If this session already wrote one,
     link it — never create a duplicate.
   - If none exists, write one at `100_Todo/drafts/handover-<slug>-<today>.md` (kebab-case
     slug, date from system time — run `date` first). Write it for a cold-start agent
     session: frontmatter (`date / type: handover / task / for: any follow-up agent
     session / status`), one-paragraph context, key file paths, what's done, what remains
     (as a checklist), and any rules the next session must follow.
   - Obsidian formatting: no blank line between the closing frontmatter delimiter and the
     first content line.

3. **Append the task line** to `000_Agent/dashboard/build-box.md` (create the file if
   missing):
   ```
   - [ ] <task name> → [[100_Todo/drafts/handover-<slug>-YYYY-MM-DD|handover]]
   ```
   Exact format matters if a renderer parses it — `- [ ]` marks open items and the
   `[[...]]` target is the chip's link. Skip the append if ANY line — checked or
   unchecked — already links to this handover doc.

4. **Re-render the dashboard (only if you have a renderer):**
   ```bash
   python3 "$VAULT/000_Agent/scripts/dashboard-render.py"
   ```
   If no renderer script exists, skip this step silently.

5. **Report** in one or two lines: the chip label, the handover doc it links to, and a
   reminder that ticking the checkbox in `build-box.md` clears the task.

## Completing / removing a task

Tick its checkbox in `000_Agent/dashboard/build-box.md`. Don't delete lines; checked
lines are the done-history. If the user says a parked task is done, tick it there (and
re-run the renderer if one exists).
